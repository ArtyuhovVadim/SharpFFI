# Анализ архитектуры проекта SharpFFI

## Главная идея и философия
**SharpFFI** решает проблему сложного interop-взаимодействия между C/C++ и C#. Существующие генераторы часто требуют сложных и нестандартных конфигурационных файлов, а анализ C/C++ кода — это нестабильный и тяжелый процесс. 

SharpFFI «переворачивает» этот подход:
*   **C# как Source of Truth (источник истины)**: Анализируется не C/C++ код, а сам C# код. Вся конфигурация задается через C#-атрибуты (например, `[FixedString]`, `[Handle]`), что избавляет от боли внешних конфигурационных файлов.
*   **Максимальная производительность и Zero-Allocation**: Упор на ручной контроль, маппинг памяти 1 к 1 и отсутствие скрытых аллокаций мусора (GC). 
*   **Лучше написать чуть больше кода в C#, но получить 100% контроль** и прозрачный API, чем бороться с черным ящиком чужого генератора.

## Структура решения
Проект разбит на несколько логических слоев:

1.  **`SharpFFI.Primitives`**
    *   Здесь лежат высокопроизводительные типы (примитивы) для маппинга. 
    *   **Строки**: Реализована мощная система zero-allocation строк, разделенная по кодировкам (`Utf8` и `Utf16`). Типы вроде `Utf8StringView`, `Utf16CString`, `NativeUtf8CString` позволяют работать с сишными строками напрямую, как со спанами (Span), без выделения памяти в куче.
    *   **Другие примитивы**: Типы с явным размером вроде `Bool8`, `Bool32` для безопасного маппинга.
2.  **`SharpFFI.Polyfills`**
    *   Содержит бекпорты современных фич (например, `Rune`, `Marvin`, утилиты `Utf16Utility`) для совместимости с `.NET Standard 2.0`, чтобы примитивы работали везде.
3.  **`SharpFFI.Generators.*` (Core, C, Cpp)**
    *   Roslyn Source Generators, которые реализуют ту самую идею генерации бойлерплейта по C# атрибутам. Архитектура построена на базе `IIncrementalGenerator` для оптимальной производительности в IDE.
4.  **`SharpFFI.Test`**
    *   Проект-песочница. Демонстрирует работу с указателями и строками (`Utf8StringView` по байтовому массиву, слайсинг строк и их in-place изменение).
